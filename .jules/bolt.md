## 2024-05-30 - [Performance] Offloading Deep File Scans to Background Threads in Textual
**Learning:** During the initial Textual UI loading phase (e.g., `on_mount`), running potentially expensive unbounded I/O operations—like deep file scanning with `Path.rglob`—synchronously on the main thread can block the UI. Passing a generator to `call_from_thread` or evaluating it on the main thread nullifies the benefits of the background thread because the I/O operations are still executed synchronously on the main UI thread.
**Action:** When offloading I/O operations in Textual apps via `@work(thread=True)`, ensure the operation (such as a generator from `Path.rglob`) is fully evaluated (e.g., cast to a `list`) *within* the background worker thread before passing the complete data set to `call_from_thread()` to be rendered.
