## 2025-02-18 - Textual background workers and generators
**Learning:** When using Textual's `@work(thread=True)` decorator to offload I/O tasks like file scanning, simply returning the generator from the worker thread isn't enough. If the generator is iterated over in the main thread (e.g. inside the `call_from_thread` callback), the I/O operations will still block the main thread. Additionally, UI state resets should happen within the `call_from_thread` callback to prevent race conditions that result in duplicate UI elements if the worker is triggered multiple times rapidly.
**Action:** Always fully evaluate generators or iterators into a concrete data structure (like a `list`) *inside* the background worker thread before passing them to `call_from_thread`. Group UI state resets with the population of new data in the callback to ensure atomicity.
