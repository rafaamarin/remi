## 2024-05-15 - Unbounded directory scanning during startup
**Learning:** In Python, `Path.rglob()` searches deeply and recursively, and checking `next(entry.rglob("*.wav"), None)` inside the project root during UI load can cause a significant synchronous delay (blocking the main thread) if the project contains deeply nested directories (e.g. `node_modules`, `venv`). The initial UI loading phase scanned all root directories searching for any `.wav` file deeply inside them, although actual kit loading (`load_kit_from_dir`) only performed a shallow `glob("*.wav")` directly under the directory. This inconsistency meant that the UI would list a library if a `.wav` was deep inside, but clicking it would not load anything since it only checks shallowly.
**Action:** Replaced `rglob` with a shallow `glob` in `scan_libraries` to be consistent with how `load_kit_from_dir` actually behaves, removing the deep scan performance bottleneck during initial startup.
